# MindFusion: iterative "diffusion" writing with you as the generator

MindFusion is a local web notepad. The user writes rough notes, taps **✦ Diffuse**, and a
polished version appears as a new node in a branching version tree. Every diffusion is
generated by **you, the agent running this skill**, through a small bridge script. This
works with any agent harness that can run a background shell command and react when it exits
(Claude Code, Codex, Gemini CLI, Antigravity, and others).

If no agent is listening, the server falls back to a headless agent CLI it finds on PATH
(`claude`, `codex`, `gemini`, `agy`, or whatever `MINDFUSION_AGENT_CMD` is set to), then to
the Gemini/OpenAI APIs if keys are set.

All paths below are relative to the project root.

## Step 1: Start the server

```bash
bash .agents/skills/mindfusion/scripts/start_server.sh --port 8765 --open-browser
```

- Starts the server in the background (or reuses a running one) and opens the page.
- Check it is up: `curl -sS http://127.0.0.1:8765/api/state >/dev/null && echo up`.
- The server needs normal network/filesystem access. If your harness sandboxes commands,
  run this one unsandboxed.
- Set `MINDFUSION_AGENT_NAME` (e.g. `"Claude Code"`) to label yourself in the UI.

## Step 2: Tell the user how to use it

Tell the user the page is live at **http://127.0.0.1:8765**. On the same network, a phone
can use `http://<this-machine-ip>:8765`. Then explain the workflow:

- **Write** rough notes or an outline on the page, then tap **✦** (or press ⌘/Ctrl+Enter).
- **Steer** with instructions on a line of their own starting with `//`
  (for example `// add a comparison table`). They can also select text and tap **//** to
  attach a comment to that text.
- **Edit** any version directly. Edits are kept as a draft on top of that version. The next
  diffusion uses the draft, or the user can save it as its own version from the version menu.
- **Explore** with the **v‹n›** menu: jump between versions, branch from any of them, and
  compare a version with its parent (**±**).
- **Cancel** a running diffusion by tapping the spinning button.

## Step 3: Listen for diffusion requests

Run the listener as a **background** command. It blocks until the user taps ✦, prints the
job, and exits with code 0. That exit is what wakes you up.

```bash
python3 .agents/skills/mindfusion/scripts/agent_bridge.py --agent-name "<your name>" listen
```

How to run it in the background depends on your harness:

- **Claude Code:** Bash with `run_in_background: true`. You get a notification when it exits.
- **Antigravity:** `run_command` with `IsDaemon: false` and `WaitMsBeforeAsync: 500`.
- **Other harnesses:** any background or async command whose completion notifies you.

While the listener is connected, the UI dot is green ("live session"), and new diffusions go
to you instead of the fallback CLI.

## Step 4: When woken with `DIFFUSE_REQUESTED`

The listener prints `{"event": "DIFFUSE_REQUESTED", "jobs": [...]}`. For each job:

1. Read these fields:
   - `working_content`: the current page as HTML, with `//` lines already removed.
   - `comments`: what to change. Each comment has `comment` (the instruction) and `quote`
     (the text it refers to). Lines the user typed as `//` come through here too, with
     `source: "inline"`. Address every comment.
   - `seed_outline`: a plain-text copy of the page.
   - `params.strength`: how freely to rewrite, from 0.1 (light polish) to 1.0 (full rewrite
     and expansion).
2. Write the new version as a **semantic HTML fragment**. Use whichever tags suit the
   content: `<h1>`–`<h3>`, `<p>`, `<ul>`/`<ol>`, `<blockquote>`, `<table>`,
   `<pre><code>`, `<details>`, `<img src="https://…" alt="…">`, `<mark>`, `<strong>`,
   `<em>`. Don't include `<html>`, `<head>` or `<body>`. Don't use scripts, inline styles or
   code fences. The UI strips scripts and styles anyway.
3. Save it to a file and push it:
   ```bash
   python3 .agents/skills/mindfusion/scripts/agent_bridge.py --agent-name "<your name>" push \
     --job-id <job_id> \
     --title "Document Title" \
     --summary "One line on what changed" \
     --content-file /path/to/output.html
   ```
   If the user cancelled the job in the meantime, the push is refused with HTTP 409. That's
   expected; skip it.
4. **Restart the listener right away** (Step 3), so the next tap on ✦ reaches you again.

## Other bridge commands

- `agent_bridge.py status`: shows the active version, its unsaved `draft`, open comments and
  pending jobs.
- `agent_bridge.py push --content-file f.html` without `--job-id`: adds a version on top of
  the current one, even when the user didn't ask for a diffusion.
